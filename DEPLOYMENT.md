# Развёртывание

## Требования

Linux и доступ к Telegram. V2 использует Docker Engine + Compose. Если Docker отсутствует, start.sh автоматически устанавливает его на поддерживаемой Ubuntu/Debian, без отдельного подтверждения. Нужен root/sudo; запрос пароля sudo выполняет сама система. Исходники не содержат действующих ключей; создайте собственное приложение Telegram и бота.

## Готовый образ: без исходников и сборки на сервере

Скопируйте команду из [README](README.md). Нужны Bash, curl, Интернет и root/sudo для установки Docker, если его ещё нет. Python и Git на сервере не нужны. Публичная установка не требует GitHub-токена.

Установка создаёт ~/tg-antidel-bot. Путь переопределяется TG_GUARD_INSTALL_DIR. Чужой непустой каталог без маркера установщика не перезаписывается. Скачиваются start.sh, compose.prebuilt.yaml и scripts/Install-Docker.sh; приложение находится в готовом образе linux/amd64. Выбирается commit последней успешной ручной сборки container.yml, образ закрепляется по digest в .image-ref.

Для повторного запуска выполните bash start.sh из каталога установки, для перенастройки — bash start.sh --setup. Повторная команда установки обновляет файлы и образ, сохраняя data. Приватная копия также поддерживается через TG_GUARD_REPOSITORY и скрытый ввод GitHub PAT (repo, read:packages); его Docker-авторизация временно хранится в /dev/shm и удаляется после pull.

### Выпуск образа владельцем

Actions → Build container manually → Run workflow. Только ручной запуск: тесты, сборка и публикация образа с тегом sha-<commit>. Для публичной установки пакет GHCR также должен иметь public visibility; открытость репозитория не открывает пакет автоматически. Автоматической публикации на каждый push нет.

## Альтернатива: сборка из исходников

```bash
git clone https://github.com/TotKirich/tg-antidel-bot.git && cd tg-antidel-bot && bash start.sh
```

Этот вариант требует Git. Python на хосте также не нужен: используется базовый образ python:3.12-slim. При первом запуске загружаются базовый образ и Python-зависимости, последующие сборки используют кеш.

В распакованном проекте:

```bash
bash start.sh --docker
```

Скрипт собирает образ, создаёт `data/`, использует UID/GID запускающего пользователя и запускает два сервиса в фоне. В терминале появится полная временная ссылка с ключом после `#`. Откройте её, введите API ID/hash, авторизуйтесь и подключите бота. Одного адреса без ключа недостаточно.

Сервисы имеют `restart: unless-stopped`. Для автозапуска после загрузки сам Docker также должен быть включён в автозапуск. На Docker Desktop требуется поддержка host networking; основной целевой сервер — Linux.

Launcher использует Compose project `tg-antidel`. Для команд обслуживания указывайте тот же проект, каталог данных и UID/GID:

```bash
export TG_GUARD_DATA_DIR="$PWD/data"
export TG_GUARD_UID="$(id -u)" TG_GUARD_GID="$(id -g)"
docker compose -p tg-antidel ps
docker compose -p tg-antidel logs --tail 50 userbot
docker compose -p tg-antidel stop
```

`stop` сохраняет данные. Не используйте параллельные Compose projects поверх одной папки сессии. Для изменения имени проекта предусмотрен `TG_GUARD_PROJECT`; для дополнительного Compose-файла — `TG_GUARD_COMPOSE_OVERRIDE`. При обновлении уже существующей установки явно укажите её фактический каталог `TG_GUARD_DATA_DIR` и тот же project name.

## Адрес входа

Новый launcher выбирает конкретный частный IPv4 локального интерфейса, иначе `127.0.0.1`; порт — 8080. Существующая конфигурация сохраняет прежние значения. Явный адрес новой установки:

```bash
TG_GUARD_AUTH_HOST=127.0.0.1 TG_GUARD_AUTH_PORT=8080 bash start.sh --docker
```

Для удалённого сервера откройте на своём компьютере туннель:

```bash
ssh -L 8080:127.0.0.1:8080 user@server
```

Затем откройте полную ссылку из терминала запуска. Если терминал закрыт, она находится в `data/.auth-login.url`. Не публикуйте этот файл и не сохраняйте ссылку в issue. Сервисы намеренно не пишут её в журналы.

Прямой доступ по LAN поддерживается через конкретный локальный IPv4. HTTP передаёт ввод без шифрования; используйте его только в доверенной сети. Не настраивайте публичный проброс порта. `0.0.0.0` не принимается. После настройки listener закрывается; при незавершённом входе остаётся открыт в ожидании владельца. Он может открыться снова при отзыве сессии или запросе настройки бота.

## Настройка Telegram и бота

1. Откройте [my.telegram.org/apps](https://my.telegram.org/apps), раздел API development tools. Создайте приложение, скопируйте API ID и API hash в мастер.
2. Войдите по QR: Telegram на телефоне → Настройки → Устройства → Подключить устройство. Альтернатива — телефон и код способом, который назначил Telegram; доставка SMS или кода в приложение не гарантируется сервисом. При необходимости введите 2FA.
3. Откройте [@BotFather](https://t.me/BotFather), выполните `/newbot`, выберите имя/username и введите токен в мастер. Токен проверяется через getMe.
4. Откройте созданного бота и нажмите `/start`. Без начала личного диалога Telegram может запрещать уведомления.

Числовой ID владельца/получателя берётся автоматически. Username не даёт прав администратора. Закрытая группа-архив создаётся фоновым worker; известный автор получает одну тему независимо от исходной переписки.

Повторная настройка: `bash start.sh --setup`. Пустые поля сохраняют текущие ключи; перенастройка не стирает данные. Другому владельцу нужна новая пустая папка.

В боте доступны `/status`, `/check_bot`, `/settings` и кнопки управления. `/settings` открывает форму проверки/замены токена. Если старый токен недействителен, используйте `bash start.sh --setup`; работающий userbot также обрабатывает файл `.notification-setup.request` в каталоге данных.

## Автоматическая установка Docker

Если команда docker отсутствует, start.sh вызывает `scripts/Install-Docker.sh`. Поддерживаются Ubuntu 22.04/24.04/26.04/26.10 и Debian 12/13 с systemd. Действия: установить ca-certificates/curl, загрузить официальный GPG-ключ Docker, добавить подписанный apt-репозиторий, установить Docker Engine/CLI, containerd.io, Buildx и Compose plugin, включить Docker в автозапуск и запустить daemon.

Установка выполняется автоматически с apt-get -y; если нужны права, используется sudo. Скрипт не передаёт скачанный shell-код в интерпретатор, не добавляет пользователя в группу docker и не включает TCP-доступ daemon. После установки launcher может выполнять Docker через sudo, сохраняя UID/GID пользователя для контейнеров.

Если уже есть конфликтующие пакеты container runtime или частично настроенный репозиторий Docker, установка останавливается с объяснением; пакеты и контейнеры не удаляются. Существующий Docker не переустанавливается. Если у него отсутствует Compose plugin, установите docker-compose-plugin в рамках существующего способа установки. Другие ОС не изменяются автоматически.

Инструкция использует официальную процедуру [Ubuntu](https://docs.docker.com/engine/install/ubuntu/) / [Debian](https://docs.docker.com/engine/install/debian/). Установщик покрыт проверками логики и подменёнными системными командами; установка пакетов на реальной пустой ОС в рамках подготовки версии не выполнялась.

## Данные и настройки

`data/` содержит config.json, Telegram-сессию, SQLite/WAL, медиа, журналы и служебные файлы. Каталог и резервные копии приватны. Приложение не шифрует их на диске.

| Параметр | Новая установка | Назначение |
|---|---|---|
| archive_mode | forum | forum: закрытая группа; saved: log_chat_id |
| log_chat_id | me | Избранное в режиме saved |
| retention_days | 14 | Локальный срок хранения; не удаляет отправленные копии Telegram |
| max_media_mb | 100 | Ограничение размера одного файла |
| min_free_mb | 512 | Резерв места для скачивания |
| stories_enabled | true | Доступные сторис контактов |
| stories_poll_seconds | 300 | Интервал сверки, минимум 60 секунд |
| auth_port | 8080 | Порт нового мастера |
| recheck_hours | 24 | Окно перепроверки, в пределах retention |
| recheck_batch_size | 50 | Пакет перепроверки, 1–100 |
| notify_public_deletions | true | Уведомления об удалениях из каналов |

`config.example.json` — шаблон совместимых настроек; копировать его для мастера не требуется. Старые конфигурации могут иметь saved/8787. Изменения параметров мониторинга требуют перезапуска, переключатели уведомлений и токен перечитываются в работе.

## Обновление и резервные копии

Перед обновлением остановите оба сервиса и сохраните всю папку данных с закрытыми правами. Копирование SQLite вместе с WAL/SHM надёжно выполнять при остановленных процессах; для работающей БД используйте SQLite backup API. Сессия даёт доступ к аккаунту — резервная копия столь же чувствительна.

Обновляйте только исходники, оставляя фактическую папку данных прежней. Запускайте с тем же Compose project/UID/GID. После запуска проверьте `/status`, свежесть связи с Telegram, очередь отправки и свободное место. Один статус контейнера running не доказывает доставку всех сообщений.

Известные ограничения тем и скачивания перечислены в разделе ниже. Не стирайте SQLite или очередь для устранения ошибки: там находятся привязки архива и задания повторов.

## Известные ограничения V2

- После аварии между отправкой и подтверждением задания возможен дубль.
- Удалённая вручную или недействительная тема может вызвать TOPIC_ID_INVALID; автоматическое исправление всех случаев пока не реализовано.
- Отдельные задания медиа могут оставаться в повторах с ValueError и требуют диагностики. Статус running не подтверждает обработку каждой записи.
- Недоступность при перепроверке не всегда доказывает удаление; сервис различает событие Telegram и недоступность.

## Переход с V1

Сделайте резервную копию всей старой установки, остановите старые userbot/notifybot и отключите их автозапуск. V2 устанавливайте в отдельный каталог: не запускайте две копии с одной Telegram-сессией. Старые данные не удаляйте. Миграция произвольных баз V1 не гарантируется; безопасный первый запуск — с новой папкой данных и входом через мастер. Для отката сначала остановите V2, затем включите прежние процессы.

## Подписки и точечные настройки каналов

Обработка каналов ограничена подписками аккаунта. Список загружается перед захватом событий и обновляется каждые пять минут; событие изменения канала сбрасывает кеш его подписки. У нового или неизвестного канала членство проверяется через Telegram. Ошибка проверки не считается подтверждением подписки. Если подтверждение старше десяти минут, обработка соответствующего канала приостанавливается до успешной проверки; личные чаты и группы не подпадают под этот фильтр. Обновление Telegram после выхода из канала может приходить с задержкой.

Кнопка «🎯 Отключить точечно» и /channels показывают подписанные каналы страницами по шесть. У каждого два независимых переключателя: сохранение (включая архив, правки, медиа и перепроверки) и уведомления бота. Уведомления требуют включённого сохранения и общих разрешений уведомлений/пабликов. При отключении сохранения новые сообщения не записываются; ранее сохранённые данные не удаляются. Настройки сохраняются в SQLite и переживают перезапуски и обновление списка.

В любом разделе бота можно отправить @логин или логин без @: для найденного среди подписок канала откроется карточка с текущими настройками. Сам ввод не меняет их: выберите отдельную кнопку сохранения или уведомлений. «Отключить уведомления» полностью прекращает их отправку для канала, а не только убирает звук. Список и карточка читают текущие значения из БД при каждом открытии и нажатии; переключение сразу обновляет ту же карточку. Для каналов без username используйте кнопки. Список и переключатели доступны только владельцу в его личном чате с ботом.

После обновления откройте /start или «Статус», чтобы получить новую клавиатуру. Переход с БД v7 на v8 автоматический; перед обновлением сохраните резервную копию data. Старый код v7 не читает БД v8: для отката требуется прежняя резервная копия при остановленных контейнерах. При временно неподтверждённой подписке очередь ждёт повторной проверки. При подтверждённом выходе из канала или ручном отключении неподходящие задания отправки отбрасываются, а скачивания отключённых каналов приостанавливаются; включение сохранения не запускает отдельную загрузку старой истории.
