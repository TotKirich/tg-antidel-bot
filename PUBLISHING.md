# Подготовка и выпуск релиза

Публикуется только проверенный набор из `scripts/Build-Release.py`. Действующие config.json, data, Telegram-сессии, базы, журналы и медиа не входят в него. Тесты остаются в исходниках, но не попадают в runtime-образ. Старые systemd-скрипты в V2 не используются.

## Проверка и чистые архивы

```bash
docker build --target test -t tg-antidel-bot:test .
docker run --rm --network none tg-antidel-bot:test
python scripts/Build-Release.py --publish-dir publish/new-release
```

Каталог назначения должен быть новым. Получаются полный архив исходников и `tg-antidel-bot-runtime.zip` без тестов и инструментов подготовки. Просмотрите состав, выполните проверку секретов и сравните с публикуемым коммитом. У config.example.json значения ключей должны быть пустыми.

## Релиз в основном репозитории

1. Добавьте проверенный состав в TotKirich/tg-antidel-bot обычным коммитом, сохраняя историю. Удалите из текущего дерева устаревшие файлы и действующую конфигурацию.
2. В Actions запустите **Build container manually**. Дождитесь успешных тестов и публикации `ghcr.io/totkirich/tg-antidel-bot:sha-<commit>`.
3. Для установки без GitHub-токена пакет GHCR должен быть публичным. Открытость репозитория сама не меняет видимость пакета. Проверьте анонимное скачивание установщика и manifest образа.
4. Создайте GitHub Release с тегом версии, описанием изменений, ограничениями и двумя проверенными ZIP-архивами.

Установка берёт последний успешный ручной workflow. Изменения документации после сборки не требуют нового образа; изменения кода и установщика требуют новой сборки. Автоматической публикации на каждый push нет.

Чистый новый коммит не очищает старую историю и не отзывает опубликованные ранее секреты. При утечке сначала отзовите затронутые ключи/сессии; см. [SECURITY.md](SECURITY.md). Рабочую установку и личные данные не копируйте в каталог публикации.
